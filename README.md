# منصّة Bac Arabe Sénégal

منصّة تعليمية عربية متكاملة (RTL) لبرنامج **«الدليل الشامل لمنهجية الإجابة في التاريخ والجغرافيا»** —
موجّهة لطلبة البكالوريا، بإشراف الأستاذ زكريا سي.

منصّة كاملة وليست صفحة تعريفية: واجهة تسويقية، مصادقة، لوحة طالب، تدرّج إجباري في الدروس،
اختبارات وحدات، باقتان (START / PREMIUM ELITE)، دفع إلكتروني معياري، ولوحة إدارة كاملة.

---

## ١. التشغيل السريع

```bash
npm install
npm run db:push      # إنشاء الجداول
npm run db:seed      # بذر المنهج الكامل + الباقات + حساب المسؤول
npm run dev          # http://localhost:3000
```

المشروع مضبوط افتراضيًا على **SQLite** (ملف `prisma/dev.db`) ليعمل فورًا بلا خادم قاعدة بيانات.

### حسابات التجربة

| الدور | البريد | كلمة المرور |
|---|---|---|
| مسؤول | `admin@bacarabe.sn` | `Admin@2026` |
| طالب (PREMIUM) | `student@bacarabe.sn` | `Student@2026` |

> غيّر كلمة مرور المسؤول قبل النشر، وعدّل `ADMIN_EMAIL` / `ADMIN_PASSWORD` في `.env`.

---

## ٢. الانتقال إلى PostgreSQL (الإنتاج)

```bash
npm run db:use-postgres
# ثم عدّل DATABASE_URL في .env إلى رابط Neon / Supabase / خادمك
npx prisma db push
npm run db:seed
```

المخطط مكتوب عمدًا بأنواع محايدة (بلا `enum` أو `json` خاصّين بـ Postgres)،
لذلك التبديل بين المزوّدين لا يتطلّب أي تعديل في الكود.

## ٤. نظام التدرّج الإجباري (Sequential Learning)

القاعدة المطبَّقة في `src/lib/curriculum.ts`:

```
الدرس ١ → إتمام → الدرس ٢ → … → إتمام كل دروس الوحدة
→ اختبار الوحدة → النجاح (٧٠% افتراضيًا) → فتح الوحدة التالية
```

- كل حالات القفل تُحسب **في الخادم فقط**. تعديل الرابط مباشرة (`/learn/<id>`)
  لا يفتح درسًا مقفلًا — تظهر صفحة «هذا الدرس مقفل» مع سبب القفل.
- الإجراءات (`completeLessonAction`، `submitQuizAction`) تعيد التحقّق من الصلاحية
  قبل أي كتابة في قاعدة البيانات.
- تقدّم الطالب يُحفظ تلقائيًا، ويعود عند دخوله التالي إلى «متابعة التعلّم».

أسباب القفل الممكنة: `subscription` (بلا اشتراك) · `plan` (يتطلّب PREMIUM) ·
`sequence` (لم يُتمّ السابق) · `quiz` (استنفد المحاولات).

كل هذه القواعد قابلة للتعطيل من **لوحة الإدارة ← الإعدادات** دون لمس الكود.

### الاختبارات ومراجعتها

- خمسة أنواع أسئلة: اختيار من متعدد، متعدد الإجابات، صح/خطأ، سؤال قصير، سؤال تطبيقي.
- الأسئلة القصيرة تُصحَّح آليًا بمقارنة ذكية تتجاهل التشكيل وصيغ الألف والهاء والأرقام العربية.
- **الأسئلة التطبيقية** لا تُحتسَب في التصحيح الآلي، وتُعلَّم `needsReview` لتصحيح الأستاذ
  في `/admin/reviews` — وهي إحدى مزايا باقة PREMIUM ELITE.
- بعد كل محاولة يفتح الطالب **صفحة مراجعة** تعرض كل سؤال بإجابته، صحّتها،
  الإجابة الصحيحة وشرحها (يمكن إخفاء الأخيرين من الإعدادات).
- إن ضُبطت مدّة زمنية للاختبار، يظهر مؤقّت تنازلي ويُرسَل الاختبار تلقائيًا عند انتهائه.
- تُسجَّل لكل محاولة: الدرجة، النقاط، التاريخ، رقم المحاولة، وحالة النجاح.

## ٦. بوابات الدفع

الطبقة معيارية: كل بوابة ملفّ واحد ينفّذ الواجهة `PaymentProvider`.

| البوابة | الملف | الحالة |
|---|---|---|
| Wave (السنغال) | `lib/payments/wave.ts` | جاهزة — تحتاج `WAVE_API_KEY` |
| Orange Money | `lib/payments/orange-money.ts` | جاهزة — تحتاج مفاتيح OAuth |
| CMI (المغرب) | `lib/payments/cmi.ts` | جاهزة — تحتاج `CMI_STORE_KEY` |
| تحويل يدوي + إيصال | `lib/payments/manual.ts` | تعمل فورًا بلا مفاتيح |

**تفعيل بوابة:** أضف معرّفها إلى `PAYMENT_PROVIDERS` في `.env` وأضف مفاتيحها.
البوابات غير المهيّأة لا تظهر للطالب، وتظهر حالتها في **لوحة الإدارة ← المدفوعات**.

**إضافة بوابة جديدة (Stripe مثلًا):**
1. أنشئ `src/lib/payments/stripe.ts` ينفّذ `PaymentProvider`.
2. سجّله في `REGISTRY` داخل `src/lib/payments/index.ts`.
3. أضف `stripe` إلى `PAYMENT_PROVIDERS`. لا تعديل في أي مكان آخر.

**عنوان الـ Webhook:** `POST /api/payments/webhook/<provider>`

> الوصول إلى المحتوى المدفوع يُمنَح حصريًا عبر `activateSubscription`،
> وهي تُستدعى فقط بعد تأكيد الدفع أو موافقة المسؤول.

## ٧. لوحة الإدارة

`/admin` — متاحة لحسابات `role = "admin"` فقط.

- **الإحصائيات:** عدد الطلاب، النشطون، مشتركو كل باقة، إجمالي المبيعات،
  معدّل الإكمال، متوسّط نتائج الاختبارات، أكثر الدروس مشاهدة، الطلاب المتوقّفون.
- **المحتوى:** إضافة/تعديل/حذف الوحدات والدروس، ترتيب الدروس، النشر والإخفاء،
  روابط الفيديو، رفع ملفات PDF والموارد.
- **الاختبارات:** إنشاء الأسئلة (اختيار من متعدد، متعدد الإجابات، صح/خطأ،
  قصير، تطبيقي)، تحديد درجة النجاح وعدد المحاولات والمدّة الزمنية.
- **التصحيح (`/admin/reviews`):** تصحيح الأسئلة التطبيقية التي لا تُصحَّح آليًا،
  مع ملاحظات مكتوبة تصل الطالب. تُعاد النتيجة تلقائيًا على مجموع الأسئلة،
  وقد تُفتح الوحدة التالية إن تجاوزت درجة النجاح.
- **البرنامج والمسارات (`/admin/content/course`):** عنوان البرنامج ووصفه
  والمدرّس والمدّة، وإضافة/تعديل/حذف المسارات (المواد) وترتيبها.
- **الواجهة (`/admin/appearance`):** استبدال صور الصفحة الرئيسية — بطاقة الأستاذ
  وشبكة الملصقات — رفعًا من الجهاز أو اختيارًا من صور الهوية الجاهزة، مع
  الترتيب والحذف والإضافة (حتى ٨ صور) وزرّ استعادة الصور الأصلية.
- **فيديو التعريف (`/admin/appearance#video`):** قسم يظهر مباشرة بعد أعلى الصفحة
  الرئيسية. رابط يوتيوب/فيميو (مُستحسَن) أو رفع ملف MP4/WEBM حتى ٣٠٠ ميغابايت
  عبر `/api/admin/upload-video` (كتابة تدريجية على القرص، للمسؤول فقط)،
  مع عنوان ووصف وصورة غلاف. المشغّل لا يُحمَّل إلا عند الضغط، والقسم يُخفى
  تلقائيًا ما دام الرابط فارغًا.
- **أكواد الخصم والإحالة (`/admin/coupons`):** نسبة مئوية أو مبلغ ثابت، مقيّدة
  بباقات معيّنة، بحدّ أقصى للاستعمال وتاريخ انتهاء، مع «صاحب الكود» لتتبّع
  الإحالات (عدد المشتركين والمبيعات لكل كود). الخصم يُحسب في الخادم عند إنشاء
  عملية الدفع، ويُحتسب الاستعمال عند تأكيد الدفع فقط. رابط الإحالة
  `/checkout/start?code=PROF10` يطبّق الكود تلقائيًا، وكود 100% يفعّل الاشتراك
  مباشرة دون بوابة دفع.
- **الطلاب:** بحث، تقدّم كل طالب، آخر درس وصل إليه، نتائج اختباراته،
  منح/إلغاء اشتراك، إيقاف حساب، تصفير التقدّم.
- **المدفوعات:** مراجعة الإيصالات، تأكيد أو رفض العمليات، حالة البوابات.
- **الباقات:** الأسعار والعملة والمزايا والشارات.
- **الإعدادات:** قواعد التدرّج، الاختبارات، الشهادات، التسجيل، بيانات التواصل.

## ٨. رفع فيديوهات الدروس

الدروس مبذورة بلا فيديو. لإضافة فيديو:

**لوحة الإدارة ← المحتوى ← اختر الدرس ← «رابط الفيديو»**

المدعوم: يوتيوب، فيميو، Bunny Stream، أو رابط MP4 مباشر
(يُطبَّع الرابط تلقائيًا في `src/lib/video.ts`).

> للمحتوى المدفوع يُنصح بـ **Bunny Stream** أو **Mux** لأنهما يدعمان
> الروابط الموقّعة ومنع التحميل، على خلاف يوتيوب.

## ٩. الملفات والتخزين

- الافتراضي: تخزين محلي في `public/uploads/` (`STORAGE_DRIVER=local`).
- الصيغ المقبولة: JPG · PNG · WEBP · PDF، بحدّ أقصى ٨ ميغابايت.
- للانتقال إلى S3/R2/Bunny: نفّذ الفرع المقابل في `src/lib/storage.ts`
  وغيّر `STORAGE_DRIVER`. التوقيع نفسه لا يتغيّر.

> على Vercel لا يبقى القرص المحلي بين النشرات — استعمل تخزينًا سحابيًا في الإنتاج.

## ١٠. النشر

```bash
npm run build
npm run start
```

قبل النشر:
1. `npm run db:use-postgres` واضبط `DATABASE_URL`.
2. ولّد `AUTH_SECRET` قويًا:
   `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`
3. اضبط `NEXT_PUBLIC_SITE_URL` على نطاقك (يُستعمل في روابط العودة من بوابة الدفع).
4. أضف مفاتيح بوابات الدفع، وسجّل عنوان الـ Webhook لديها.
5. غيّر كلمة مرور المسؤول.

## ١١. المنهج المبذور

**التاريخ** (٢٣ درسًا)
1. منهجية كتابة الإنشاء التاريخي — ١١ درسًا
2. التعليق على الوثائق التاريخية — ٨ دروس
3. المقالة التاريخية: فن البناء والتحرير — ٤ دروس

**الجغرافيا** (٢٨ درسًا)
1. تقنيات كتابة المقالة الجغرافية — ٦ دروس
2. قراءة وإنجاز المبيانات — ١٤ درسًا
3. منهجية التعليق في الجغرافيا — ٨ دروس

المجموع: **٥١ درسًا** في **٦ وحدات**، مع **٦ اختبارات** (٣٠ سؤالًا) جاهزة.

لإعادة البذر من الصفر: `npm run db:reset`.
